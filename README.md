# kma-ocean-data-collector

기상청 API 허브(KMA API Hub)의 해양기상종합관측 API를 이용해, 독도(지점번호 22441) 파고부이의 시간별 관측 데이터를 2011-11-15부터 현재까지 장기간 자동 수집하는 파이프라인입니다.

## 왜 만들었나

기상청 API 허브의 해상 관측 API(`sea_obs.php`)는 특정 시각 하나에 대한 스냅샷만 반환하는 구조라, 장기간 시계열 데이터를 만들려면 시간 단위로 수만 번 반복 호출해야 합니다. 이 프로젝트는 그 반복 호출을 안정적으로, 무중단으로, 하루 API 쿼터 제한 안에서 자동으로 수행하도록 만든 수집 파이프라인입니다.

## 주요 기능

- **무중단 자동 수집**: 컴퓨터를 계속 켜둔 채로 두면, 실시간까지 계속 따라잡으며 데이터를 수집합니다.
- **일일 쿼터 자동 관리**: 하루 API 호출 한도(2만 건)에 근접하면 스스로 멈추고, 다음날 자정 이후 자동으로 재개합니다.
- **다중 프로세스 쿼터 공유**: 여러 스크립트를 동시에/번갈아 실행해도, 파일 기반 공유 카운터로 오늘 실제 총 호출 수를 정확히 추적합니다.
- **배치 병렬 처리**: 여러 시각을 동시에 요청해 순차 처리 대비 3~4배 빠르게 수집합니다.
- **체크포인트 기반 재개**: 중단(Ctrl+C, 절전모드, 오류 등) 후 재실행하면 마지막 처리 지점부터 이어서 진행합니다.
- **오류 유형별 처리**: HTTP 200이 아닌 모든 응답(401/403/타임아웃 등)을 실패로 명확히 구분해 별도 로그로 기록합니다.
- **결측 구간 자동 탐지·복구**: 전체 수집 기간을 실제 데이터와 대조해 빈 시간대를 찾아내고, 재조회로 복구를 시도합니다.
- **진행 상황 알림**: 1년 단위 수집 완료, 결측 복구 진행 상황 등을 Windows 팝업으로 알려줍니다 (다운로드를 막지 않는 논블로킹 방식).

## 데이터 개요

| 항목 | 내용 |
|---|---|
| 지점 | 독도 (지점번호 22441) |
| 관측종류 | 파고부이(TP=C) — 참고로 해양기상부이(TP=B)도 필터링 가능하도록 구현 |
| 수집 항목 | 유의파고(WH), 풍향/풍속, 수온, 기온, 해면기압, 습도 등 |
| 수집 주기 | 1시간 단위 |
| 수집 범위 | 2011-11-15 00:00 ~ 현재 (실측으로 데이터 시작 시점을 직접 확인) |

## 설치 및 설정

```bash
git clone <this-repo>
cd kma-ocean-data-collector
pip install requests
```

`.env.example`을 복사해서 `.env`로 만들고, 발급받은 API 인증키를 넣습니다.

```
cp .env.example .env
```

```
# .env
KMA_AUTH_KEY=발급받은_인증키
```

## 사용법

### 1) 기본 수집 시작

```bash
python collect_full_history.py
```

또는 Windows에서 백그라운드 창으로 실행:

```bash
run_collect.bat
```

- 처음 실행하면 2011-11-15부터, 이후 실행부터는 체크포인트 지점부터 이어서 수집합니다.
- 컴퓨터를 켜둔 채로 두면 자정마다 자동으로 하루 쿼터가 리셋되며 계속 수집됩니다.
- `Ctrl+C`로 언제든 안전하게 중단 가능합니다.

### 2) 결측 구간 점검/복구

전체 수집 기간을 실제 데이터와 대조해 빈 시간대를 찾고 재조회합니다.

```bash
python find_and_fill_all_gaps.py
```

### 3) 쿼터 카운터 상태 진단

공유 카운터 파일이 제대로 인식되는지 확인하고 싶을 때:

```bash
python diagnose_quota_file.py
```

## 프로젝트를 진행하며 겪은 주요 이슈와 해결

- **API 문서상 파라미터 설명과 실제 서버 동작이 다른 경우가 있어**, 항상 실제 호출로 검증 후 반영했습니다. (예: `tm` 생략 시 동작)
- **레이트리밋(401)과 일일 쿼터 초과(403)를 구분하지 못해 데이터가 조용히 누락된 적이 있어**, HTTP 상태코드 기반으로 성공/실패를 명확히 구분하고 실패 로그를 남기도록 개선했습니다.
- **여러 스크립트를 각기 다른 작업 폴더에서 실행해 데이터 파일이 분산된 적이 있어**, 병합·중복제거·재정렬하는 일회성 복구 스크립트를 만들어 데이터를 살렸습니다. (해당 사고는 복구 완료 후 정리되어 현재 저장소에는 포함되어 있지 않으며, 이후로는 `find_and_fill_all_gaps.py`가 같은 역할을 상시적으로 대신합니다.)
- **프로세스별로 따로 세던 API 호출 카운터가 실제 사용량과 어긋나는 문제**를 파일 기반 공유 카운터로 해결했습니다.
